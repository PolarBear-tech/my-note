## 23 种设计模式

[[设计模式.py]]

分为**创建型、结构型、行为型**三大类，是面向对象经典设计模式。

### 一、创建型模式（5 种）：负责对象创建

- [ ] **单例模式 (Singleton)**：保证一个类只有一个实例，提供全局访问点
- [ ] **工厂方法 (Factory Method)**：定义创建对象接口，由子类决定实例化哪一个类
- [ ] 抽象工厂 (Abstract Factory)：提供一组相关 / 相互依赖对象的创建接口，不指定具体类
- [ ] **建造者模式 (Builder)**：分步构建复杂对象，同样构建过程可生成不同表示
- [ ] 原型模式 (Prototype)：通过复制已有实例来创建新对象（克隆）

### 二、结构型模式（7 种）：组合类 / 对象形成更大结构

- [ ] **适配器模式 (Adapter)**：把一个类接口转换成客户期望的另一个接口
- [ ] 桥接模式 (Bridge)：将抽象与实现分离，两者可以独立变化
- [ ] 组合模式 (Composite)：把对象组合成树形结构，统一对待单个对象和组合对象
- [ ] **装饰器模式 (Decorator)**：动态给对象增加额外职责，不修改原有代码
- [ ] **外观模式 (Facade)**：提供一个高层简易接口，隐藏子系统复杂细节
- [ ] 享元模式 (Flyweight)：复用大量细粒度对象，减少内存开销
- [ ] **代理模式 (Proxy)**：为另一个对象提供代理，控制对它的访问

### 三、行为型模式（11 种）：对象之间通信、职责分配、算法

- [ ] **策略模式 (Strategy)**：封装一系列算法，可互相替换，算法独立于使用者
- [ ] 模板方法 (Template Method)：父类定义算法骨架，子类重写部分步骤
- [ ] **观察者模式 (Observer)**：一对多订阅通知，状态改变自动通知所有订阅者
- [ ] **迭代器模式 (Iterator)**：顺序遍历集合元素，不暴露集合内部结构
- [ ] 责任链模式 (Chain of Responsibility)：请求沿着对象链传递，链上对象处理或转发请求
- [ ] 命令模式 (Command)：把请求封装成对象，可做撤销、排队、日志
- [ ] 备忘录模式 (Memento)：捕获对象内部状态，以后可以恢复，不暴露内部
- [ ] 状态模式 (State)：对象行为随内部状态改变，把状态抽成独立类
- [ ] 访问者模式 (Visitor)：在不修改元素类前提下，定义作用于元素的新操作
- [ ] 中介者模式 (Mediator)：用中介对象解耦多对象之间复杂交互
- [ ] 解释器模式 (Interpreter)：定义语言文法，解释语言句子（极少用）
